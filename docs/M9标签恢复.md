# 重装相机后，相册里的徕卡一瞬 M9 标签消失

> **云端 M9 二瞬相关内容仅供学习参考。**

适用于已正常运行 Hybrid68 补丁的小米 15 Ultra（xuanyuan），国行 OS4.0.4.0.XOACNXM，机主用户 0。故障与修复在 r11（相机 v33、相册编辑 v15）实测。r12 安装包沿用相同的三个标记定义。

## 上次的原因

手动重装 APK 后，新拍 M9 照片在相册里没有「徕卡一瞬」标签。两个生效 APK 的哈希都正确，相册能力缓存也已启用。相机外部数据目录缺三个标记，保存日志显示 **M9 cloud container disabled; local JPEG retained**。相机只保存了普通 JPEG。相册缺少识别 M9 后处理入口所需的 RAW 和元数据。

补齐三个标记后，新拍 M9 照片的标签和右箭头恢复，点击能进入处理页。上次曾执行「卸载相机更新」，随后相机外部数据目录被重建。现有记录无法确定标记在哪一步消失。

## 1. 确认故障

1. 在相机「徕卡一瞬」中选 **M9**，新拍一张。等正式 JPEG 保存后再进相册。M3 的 Legend.MONOPAN 对应另一条保存路径。
2. 核对两份生效 APK 的 SHA-256，以已安装整包的 release.json 为准。系统显示的应用版本号可能相同。
3. 新 JPEG 缺少 Legend.M9、Legend.M9.meta 或 image/mipiraw10 时，查相机保存日志和下面的标记。三项俱全但入口缺失或点不开时，查相册媒体编辑能力和入口。

在电脑运行 **adb shell**，进入手机 shell 后执行 **su**，再运行以下只读命令。连接多台设备时，用 adb -s 选定目标设备。

~~~sh
getprop ro.product.device
getprop ro.build.version.incremental
for pkg in com.android.camera com.miui.mediaeditor; do
  apk=$(pm path "$pkg" | sed -n 's/^package://p' | head -n 1)
  [ -n "$apk" ] && sha256sum "$apk"
done

base=/data/media/0/Android/data/com.android.camera/files
ls -Zd "$base"
ls -lZ "$base/module256_m9_cloud_container.enable" \
  "$base/module256_m9_cloud_sensor_adapter.flag" \
  "$base/m9_tele_aux/m9_tele_container.enabled"
ls -lZ /data/vendor/camera/offlinelog/module256_m9_tele_container.flag
grep -E 'M9 cloud container disabled|triple-binding=pass|stage2-disabled' \
  "$base/legend_s3/event_log.txt" | tail -n 20
~~~

上次厂商目录的长焦标记仍存在，原整包的三个 KernelSU 模块也在正常运行。如果厂商侧标记缺失、模块停用，或日志出现 VerifyError、槽位超时、帧绑定失败，按对应环节查原因。

## 2. 补回缺失文件

以解压包内 **device/configure.sh** 的定义为依据，在 **/data/media/0/Android/data/com.android.camera/files** 下补齐缺失项。

| 相对路径 | 内容 |
| --- | --- |
| module256_m9_cloud_container.enable | 空文件，允许保存 M9 RAW 容器 |
| module256_m9_cloud_sensor_adapter.flag | 空文件，启用主摄 RAW 校正 |
| m9_tele_aux/m9_tele_container.enabled | 下方两行纯文本，使用 LF，第二行末尾也换行 |

~~~text
m9-tele-container-enabled-v2
physical_id=4
~~~

- 文件属主、组和 SELinux 上下文以本机现有相机外部目录为准。用 **stat -c '%u %g'** 查看 UID/GID，用 **ls -Zd** 查看上下文。新文件权限为 **0660**。
- 长焦子目录 **m9_tele_aux** 若缺失，按相机外部目录设置属主、组和上下文，目录权限为 **0770**。相机的 **files** 目录还没出现时，先打开一次相机让它建立目录。
- 可用 **printf '%s\n' 'm9-tele-container-enabled-v2' 'physical_id=4'** 生成长焦标记的内容。写完用 **ls -lZ** 核对属主、权限和上下文，再用 **cat** 核对长焦文件内容。
- 补齐后重新打开相机和相册即可复测。上次修复只补了标记文件，无需重启。

## 3. 验收

1. 用 M9 新拍 1× 和 4.3× 各一张。等 JPEG 落盘，在相册检查「徕卡一瞬」标签、右箭头和可打开的处理页。
2. 需要核对保存链时，读取新照片原 JPEG，检查 Legend.M9、Legend.M9.meta 和 image/mipiraw10。上次修复后的长焦样片具备三项标识，保存日志还记录了 triple-binding=pass。
3. 修复前拍到的普通 JPEG 已缺少 M9 RAW。遇到这类旧照片，用修复后新拍的照片验证。

同一套正常运行的补丁升级时，按发行包说明直接覆盖安装同签名 APK。曾执行卸载更新、清除应用数据或重建相机目录后再次遇到该症状，可优先核对这三个文件。
