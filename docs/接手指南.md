# 接手指南

> **云端 M9 二瞬相关内容仅供学习参考。**

目标为小米 15 Ultra 国行 `xuanyuan`、`OS4.0.4.0.XOACNXM`、Android API 37。当前发布基线 r11 使用相机 6.8.002230.0 / 680022300（补丁 v33）和相册编辑 2.10.40.4.8 / 210994048（补丁 v15）。补丁号写在文件名中，设备上的 versionCode 在多个补丁版本间相同。用 SHA-256 确认实际运行版本。

## 从发布包恢复工作基线

1. 解压 r11 ZIP，运行 `python m9.py integrity`。从 `apps/` 取相机及编辑器，从 `release.json` 获取包名、APK 哈希、ROM 和覆盖文件清单。保留一份完整发布包用来比较和回退。
2. 在独立目录用 apktool 或 baksmali 反汇编需要改动的 DEX。优先定位类和方法的调用链，然后核对资源表、ABI、JNI 入口与设备能力。6.7 和不同 6.8 构建的资源常量需要逐个重新映射。
3. 对照最小改动，保留原 APK 的资源、assets、native 库和其余 DEX。用 dexdump 解析 DEX，检查重复类、补丁方法调用与资源引用。使用 Android SDK Build Tools 校验 APK 签名和 `zipalign -c -P 16 4 <APK>`，再检查 native ELF 的 LOAD 段对齐。原有签名身份决定能否覆盖更新。
4. 用 ART 检查确实执行过的改动路径。成功安装后核对实际 APK 哈希，并复测入口、预览、最终成片和回退。进入相册后等待最终文件落盘再重开，记录预览和成片的差别。

## 模块与安装

三组 KernelSU 模块分别是 `xiaomi15_mfl_zoom_adapter`（镜头和预览）、`xiaomi15_leica_moment256_s3_save_bridge`（M3/M9 渲染和保存）以及 `xiaomi15_jpegq_super`（HDR 与 JPEG）。完整安装器检查 ROM、依赖、原生库基线和模块冲突，备份设备上已有的文件。安装成功后自动重启一次，再等解锁完成检查。遇到中断，按包内 `RECOVERY.md` 查看状态及回退。只改应用时优先覆盖已有 APK，并核对下次开机使用的 owner 副本。

## 调试定位

先核对 r11 ZIP 的完整性和真机实际生效的 APK，再按症状复现一次。需要回看开发候选的继承关系或曾经失败的方案，可以先查各轮记录。 [覆盖更新故障排查](覆盖更新故障排查.md) · [各轮改动记录](各轮改动记录.md)

| 功能 | 起点 | 验证点 |
| --- | --- | --- |
| 普通和专业调色 | 最终 JPEG 软件效果入口 `s7/b.j`，两种模式 ID 分别为 `0xa3`、`0xa7` | 快速预览、最终任务以及相册重开分别观察 |
| 水印叠加 | `HybridWatermark` 和 `l7/u` 的处理顺序 | 普通文字、AI、徕卡框、横竖拍和明显偏色的组合 |
| 两亿像素 | `PixelModule.isSaving`、`module/v.gotoGallery` 和待完成的 MIVI 任务 | 拍完马上点缩略图、等待正式 JPEG、确认 12288×16320、再拍一次 |
| 徕卡一瞬 | 相机 `classes11.dex` 的 `LegendSaveBridge`、`M9MessageBuilder`、`M9RawPack` | 新拍文件含 `Legend.M9` 和 `Legend.M9.meta`，相册可进入二瞬 |
| 长焦 RAW | `M9TeleAuxSlot`、`LegendSaveBridge.wrapM9Tele` | 同帧 RAW/LSC 绑定，使用验证过的槽位黑电平 |
| 主摄 RAW | `M9CloudSensorAdapter`、`M9MainRawPhase` | 1×、2× 实拍，分别比较上传准备、云回图和保存件 |
| 二瞬构图 | 相册编辑 `classes2.dex` 的 `M9CloudFraming` | 高置信度按原片裁切，检查 1×、2×、3× 和 4.3× |
| 账号授权 | 相册编辑 `ga0/e`、`ga0/a`、`ga0/d` | 在编辑器进程内检查真实可见账号及处理保存结果 |
