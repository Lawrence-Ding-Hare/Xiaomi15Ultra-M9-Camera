# 覆盖更新故障排查

适用于小米 15 Ultra 国行 `OS4.0.4.0.XOACNXM` 的 Hybrid68 r11。两个 APK 单独覆盖适用于已经运行正常的 Hybrid68 整包。全新安装和中断恢复请从 [r11 安装包](https://github.com/Lawrence-Ding-Hare/Xiaomi15Ultra-M9-Hybrid68-OS4040/releases/tag/r11) 解压后的安装入口、`release.json` 和 `RECOVERY.md` 开始。

## 先确认实际运行的 APK

补丁构建通常沿用应用自身的版本号。以下只读命令以 PowerShell 或支持单引号的 shell 为例，连接多台设备时用 adb 的 `-s` 选定设备。对外转发时只保留系统版本和 SHA-256。

```sh
adb shell getprop ro.build.version.incremental
adb shell 'for pkg in com.android.camera com.miui.mediaeditor; do apk=$(pm path "$pkg" | sed -n "s/^package://p" | head -n 1); printf "%s " "$pkg"; if [ -n "$apk" ]; then sha256sum "$apk" | cut -d " " -f 1; else echo MISSING; fi; done'
```

| r11 应用 | SHA-256 |
| --- | --- |
| 相机 v33 | `4cfcae5c52492bdbbb195b6cd9f1c1c3224c5e4e278fbc068eb7a3c967b2d019` |
| 相册编辑 v15 | `0cd2204997d2ae40f0854b53693ff8c9d9848d67e6bccbe34da97dd5ea2f7b75` |

## M9 新片没有「徕卡一瞬」后处理标签

1. 用 M9 新拍一张，等待正式文件落盘，检查 JPEG 内有没有 `Legend.M9`、`Legend.M9.meta` 和 `image/mipiraw10`。M3 的 `Legend.MONOPAN` 是另一条保存路径。
2. 文件缺 RAW 时，检查相机外部数据目录 `/data/media/0/Android/data/com.android.camera/files` 里的 `legend_s3/event_log.txt`。出现 `M9 cloud container disabled; local JPEG retained` 时，核对下表。出现 `VerifyError`、槽位超时或帧绑定失败时，从对应分支排查。
3. 文件有 M9 RAW，但标签缺箭头或点不开时，验证相册编辑入口和相册的媒体编辑能力缓存。相同的 Android versionCode 可能使旧缓存继续生效。 [账号与相册入口排查](M9登录排查.md)

| 相机外部数据目录内的文件 | r11 定义 |
| --- | --- |
| `module256_m9_cloud_container.enable` | 空文件，允许 M9 RAW 容器 |
| `module256_m9_cloud_sensor_adapter.flag` | 空文件，启用主摄 RAW 校正链路 |
| `m9_tele_aux/m9_tele_container.enabled` | 第一行 `m9-tele-container-enabled-v2`，第二行 `physical_id=4`，行尾换行 |

参考机在一次相机卸载更新及手动重装测试之后，两个 APK 哈希正确，三个标记缺失。已确认现有 KernelSU 模块运行正常，且 `/data/vendor/camera/offlinelog/module256_m9_tele_container.flag` 仍存在。对照 ZIP 内 `device/configure.sh` 的文件定义，以本机相机目录的属主、组和 SELinux 标签，按 0660 权限补回缺失的三个文件即可复测。独立修复只需补缺失文件。新拍长焦样片记录 `triple-binding=pass`，包含 15,728,640 字节 RAW 和 3,717 字节元数据，相册已可点开。已保存为普通 JPEG 的故障片需要重拍。

## 调色盘预览有效，进相册后成片恢复原色

用普通拍照、后置 1×，关闭实况和水印。把饱和度或对比度调到明显变化，拍完等正式文件落盘再进相册重开。首次对照后，用反馈者的原拍摄模式、倍率和开关复测。开始拍摄前在 PowerShell 录日志，验证后按 Ctrl+C。

```powershell
adb logcat -T 1 -v threadtime | Select-String 'HybridPaletteFinal|hasEffect|StyleAdjustEffect|Candy.*processSync|parallelType|cameraMode'
```

- `s7/b.j` 的补偿针对 xuanyuan、普通拍照 `0xa3` 或专业拍照 `0xa7` 的 MIVI2 并行 JPEG 任务 16，且任务里有拍摄时的 Candy 参数。
- 快速预览有 `StyleAdjustEffect`，最终任务却是 `hasEffect=false` 时，依次确认模式、任务类型和 Candy 参数有没有传到正式任务。已进入 `HybridPaletteFinal` 且最终任务 `hasEffect=true` 时，确认 Candy 输出是否成为最终 JPEG，必要时打开原 JPG 与相册显示对照。
- `Pe/b.u2()` 根据机型能力和 `camera.debug.mivi3.output.jpeg` 切分 MIVI 路径。MIVI3 判断为真时会跳过上述 MIVI2 补偿。参考机的属性为空，r11 脚本和模块文本配置未设置它。下面的只读命令可用于对照相机流配置，配置有差异时以实际拍摄日志判断。

```sh
adb shell getprop camera.debug.mivi3.output.jpeg
adb shell sha256sum /odm/etc/camera/xiaomi/mivistreamformat.json
```

参考机的流配置 SHA-256 与 r11 清单一致，为 `943fe67a993fc256dc395282ccfd62e4430866f36fa843a12536e81cdfcae9d0`。r10 与 r11 的调色相关代码一致。外部复现仍待实际生效的 APK 哈希和同一张照片的保存日志。

## 徕卡水印相框提示「未识别到拍摄参数」

| 相册日志 | 定位 |
| --- | --- |
| `photo exif shoot info param is invalid` | 读取新拍原片的焦距、等效焦距、光圈、曝光时间和 ISO。旧样片曾在滤镜保存后全部缺失。v34 测试从同帧补回字段，参考机的普通相框可用。 |
| `res is leica but photo is not supported` | 编辑器 `w60/x0.a` 的模板照片机型范围判断。某些黑底、白边款配置要求 LCC 定制机型，EXIF 完整时也可能被拒绝。逐项核对模板 ID 和条件。 |

提交复现时提供系统版本、之前的整包版本、两份生效 APK 哈希、拍摄模式及滤镜。日志只摘相关分支和必要统计，公开样片使用可分享的测试物品。
