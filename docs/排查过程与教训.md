# 排查过程与教训

> **云端 M9 二瞬相关内容仅供学习参考。**

## 移植基线与资源

以 6.8 相机主干为基础，对不适配 xuanyuan 的功能按管线取 6.7 实现。早期把 18PM 调色盘类直接拷进 6.7，因 Fragment 路由没接入、资源 ID 对错，界面功能均不可用。6.7 的 `R4/n0` 已有基础逻辑，布局为 `res/layout/f8n.xml`。18PM 的 `Q4/t0` 使用 `res/layout/f62.xml`，相同布局 ID 在不同资源表对应不同条目。实况运镜焦段以设备可实际切换的镜头和驱动能力为准。

## 预览有调色，落盘变回原样

早期日志在复现前已被覆盖。重新取证时，快速预览的 Candy 任务记录了 LUT 和调色，约 1.6 秒后的最终 JPEG 路过效果任务却标记 `hasEffect=false`，随即覆盖首图。v6 对普通拍照的受影响分支使用拍摄时的效果快照，v15 补齐专业 JPEG 路径，RAW 保存仍使用传感器数据，效果留在随附 JPG。异步保存要取与本张照片绑定的任务配置。

## 水印花屏、方向与双框

底层返回 JPEG 时被当作 I420 解读，可出现花屏或只有水印的底图。改用真实输入格式，结合 EXIF 和拍摄方向处理坐标。调色与框同时开启时，曾用未加框的尺寸绘制已加框的 JPEG，造成残留双框。按实际 JPEG 尺寸绘制后，边框仍会被调色，最终把效果绘制放到水印之前。一次验收至少覆盖竖拍、横拍、AI 水印和调色＋徕卡框。

## 两亿像素提前进入相册

故障文件为 1440×1080 的 early preview。同样的拍摄配置在相机等待时能得到 16320×12288。快速点缩略图直接走 `gotoGallery`，绕过最初补上的 `isSaving`，相机关闭后最终回传失败。v13 在入口检查该任务的真实等待状态，任务结束后用户可再次进入相册。检查成片尺寸和重复拍摄比看高像素 UI 更可靠。

## 二瞬入口、倍率和构图

最初将主摄和长焦的裁切写入 M9 的 protobuf Field 7。一次 smali 参数寄存器错误可通过打包，却在 ART 触发 `VerifyError`，导致保存回退普通 JPEG，徕卡入口随容器一起消失。之后恢复倍率修改前的相机元数据链，编辑器根据原 JPEG 和云回 JPEG 的局部亮度结构估计裁切，高置信度时只裁切对应的画面。低置信度保留云结果全图。排查入口消失时，先查保存端是否真正写入两个 M9 条目及 RAW/LSC 是否绑定到同一帧。

## 二瞬偏紫、网格与清晰度

追踪同一照片的相机 JPEG、相册准备上传的文件、云回 JPEG、最终文件。用 RAW、元数据和任务来源核对配对，避免相册同名文件被看错。3×、4.3× 历史故障的紫偏在云回阶段已经存在。用同帧对照将长焦 RAW 转换黑电平从 0 改为已验证的 64，两组回图恢复正常。按当前实现仅从已配对长焦槽获取该参数。过去尝试直接改回图色度会改变原本的云端色调，相关实验未进入 r11。

主摄的 RAW 色温校准应保留。同帧调整 Bayer 采样位置后，书页的 4 像素周期起伏有所减轻。重复云任务存在波动，JPEG 色度分块也会影响观感。采样改进幅度来自同帧对照，样片的网格特征不足以推出云端模型使用的内部尺寸。清晰度对照同样显示变化主要发生在下载前，保存阶段的像素差很小。

## 编译与交付

相机应用版本号与补丁文件名是两套标记。APK、开机恢复副本、校验脚本都应引用同一代文件和哈希。打包后走独立目录解压，检查 ZIP 清单、脚本、签名、版本、DEX、载荷哈希和 16 KB 对齐。分别记录主机模拟、ART、参考机实拍和整包重装，避免把静态通过误记为实机通过。

日志分享时保留类名、分支、错误码和必要统计，移除序列号、账号和令牌、私有路径、云任务标识以及照片。公开记录使用匿名样本名和公开成品哈希。
